# K230 数字手势识别 Demo

基于 **CanMV-K230 + 计算机视觉** 的数字手势识别实践项目，面向 AIOT 社团初学者，帮助成员从运行现成 AI 模型开始，逐步理解手势识别的基本流程，并在开发板上完成实时视觉应用。

> 项目定位：先部署、再理解、后扩展。
>
> 当前 README 是项目建设模板。具体支持的数字类别、模型文件、运行效果及性能数据，需要以实际验证结果为准。

## 📌 项目简介

本项目计划利用 CanMV-K230 开发板和摄像头识别用户展示的手势，并在显示屏上输出识别结果。

预期应用场景包括：

- 👋 通过手势与设备进行简单交互
- 🔢 使用手势表达数字
- 📷 实时采集摄像头画面并进行识别
- 🤖 为后续的智能控制、交互设备等 AIOT 项目提供基础

### 项目目标

完成本项目后，成员应能够：

1. 使用 CanMV IDE 连接并运行 K230 开发板。
2. 理解摄像头图像采集和 AI 模型推理的基本流程。
3. 运行手势识别 Demo，观察并验证识别结果。
4. 理解手掌检测、手势分类和结果显示之间的关系。
5. 在现有代码基础上尝试增加交互功能。

## 🚀 快速开始

### 第一步：准备开发板

1. 确认开发板型号和对应固件版本。
2. 根据官方教程完成固件烧录。
3. 将开发板连接到电脑。
4. 打开 CanMV IDE，确认可以正常连接并运行示例程序。

官方文档：[CanMV-K230 文档](https://www.kendryte.com/k230_canmv/zh/main/ai_dev_doc.html)

> 不同 K230 板卡、固件版本和显示方式可能存在差异，请优先使用与实际硬件匹配的官方配置。

### 第二步：运行官方手势识别示例

如果当前固件已经包含 AI Demo，可以先尝试运行官方示例。

1. 打开 CanMV IDE。
2. 选择 `File → Open File`。
3. 在开发板文件系统中查找以下目录：

   ```text
   /CanMV/sdcard/examples/05-AI-Demo/
   ```

4. 打开 `hand_recognition.py`。
5. 点击运行按钮，观察摄像头画面及识别结果。
6. 根据屏幕提示，将手掌放入摄像头的有效范围内，并尝试展示不同手势。

官方文档说明，`hand_recognition.py` 示例采用手掌检测后接手势分类的处理流程。该示例的手势类别数量有限，**不能直接假定它支持数字 0–9**。

如果你的目标是识别数字手势，需要继续确认当前模型的类别标签；如果没有对应的数字分类模型，则需要寻找兼容模型，或在后续进阶阶段自行训练和转换模型。

### 第三步：验证数字识别功能

运行成功后，按照实际模型支持的类别进行测试。

建议记录以下信息：

- 模型实际支持哪些数字或手势类别。
- 不同光照条件下是否能够正常识别。
- 手掌距离摄像头较远时是否仍能识别。
- 手指被遮挡时，识别结果是否发生变化。
- 识别结果是否能够稳定显示。

在完成这些测试前，不应将项目描述为已经支持完整的数字 0–9 识别。

## 🧠 技术原理

如果采用官方常见的“手掌检测 + 手势分类”方案，整体流程如下：

```text
摄像头采集图像
       ↓
     图像预处理
       ↓
     手掌检测
       ↓
  提取手掌区域或特征
       ↓
     手势分类
       ↓
  输出识别类别与结果
       ↓
  在显示设备上呈现
```

### 1. 图像采集

摄像头持续获取当前画面，为后续视觉推理提供输入。

### 2. 手掌检测

检测模型定位图像中的手掌，确定需要进一步分析的区域。

### 3. 手势分类

分类模型根据手掌区域或相关特征判断当前手势属于哪个类别。

如果要识别数字，需要确保分类模型的标签与目标数字相对应。

### 4. 结果显示

程序将模型输出转换为便于观察的文字、类别或可视化标记，并显示在设备屏幕上。

> 说明：上述流程是该类方案的原理介绍。实际采用的模型数量、输入尺寸、预处理方法及推理接口，应以项目使用的具体官方示例和模型为准。

## 🔧 常见问题

### 1. IDE 找不到示例文件

检查固件版本和文件系统目录。部分固件版本的示例目录可能不同，也可能没有预置对应的 Demo。

### 2. 程序运行后没有画面

检查摄像头连接、显示设备配置、分辨率和固件兼容性，并查看 IDE 的报错信息。

### 3. 可以识别手掌，但不能识别数字

手掌检测和数字分类不是同一个任务。请检查当前分类模型支持的类别，以及是否使用了与数字手势对应的模型。

### 4. 模型文件无法加载

确认模型格式、模型路径、输入输出配置和当前固件支持情况。K230 部署通常需要使用兼容的 KModel 等模型格式，不能假设电脑上训练得到的 `.pt` 文件可以直接运行。

### 5. 更换模型后出现报错

模型更换可能涉及输入尺寸、预处理、输出张量结构和后处理逻辑的变化。需要同步核对模型与代码接口，而不只是替换文件。
